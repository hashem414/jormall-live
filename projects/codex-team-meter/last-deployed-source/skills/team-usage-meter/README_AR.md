# سكيل مرصد كودكس — دليل عضو الفريق

هذه الحزمة تثبّت سكيل `team-usage-meter` ومرسل أرقام صغيرًا على جهازك. السكيل وحدها ليست خدمة تعمل طوال الوقت؛ المرسل المحلي هو الذي يزامن الاستخدام تلقائيًا دون استدعاء موديل كل دقيقة.

## قبل التثبيت

الأداة تعرض **نسبة توكنز كل عضو من مجموع توكنز الفريق التي رصدناها**، وليس نسبة خصمه الرسمية من حد ChatGPT Pro. تعمل مع سجلات Codex المحلية المتوافقة؛ لا تجمع كل مهام Codex Cloud تلقائيًا. القياس يبدأ من وقت التثبيت، ولا يستورد الاستخدام القديم.

البرنامج يقرأ ملفات rollout محليًا لاستخراج العدادات ثم يتجاهل بقية المحتوى. لا يرسل ولا يعرض المحادثات أو الكود أو مسارات المشاريع أو البريد أو ملف `auth.json`. الذي يُرسل: أعداد التوكنز، وقت الرصد، معرّف جهاز عشوائي، بصمة حدث لمنع التكرار، ولقطة عددية لحدود الحساب إن سجّلها Codex. اسم العرض يحدده مدير اللوحة، ويمكن أن يكون اسمًا مستعارًا. أعضاء الفريق يستطيعون رؤية ملخص استخدام بعضهم، وليس المحادثات.

هذا لا يمنع مالكي الجهاز أو السيرفر من تعديل البرنامج، وليس تدقيقًا ماليًا مقاومًا للتلاعب. كما لا يخفي محادثات موجودة أصلًا داخل حساب ChatGPT مشترك. وفق سياسة OpenAI الحسابات الشخصية ليست للمشاركة بين أشخاص.

## التثبيت على Windows

تحتاج Node.js 20 أو أحدث على جهاز العضو، وملف `member-profile.json` الخاص بك من مدير اللوحة. لا تحتاج Docker على جهاز العضو. لا تحتاج مفتاح OpenAI API.

فك ضغط حزمة الفريق، وافتح PowerShell في مجلد `team-usage-meter` الذي يحتوي `install.mjs`. ضع ملف الربط الخاص بك خارج المستودعات العامة ثم شغّل:

```powershell
node .\install.mjs --profile "C:\path\member-profile.json" --accept --autostart
```

استبدل المسار بمسار ملفك. تشغيل هذا الأمر يعني موافقتك على إرسال الأرقام المبيّنة أعلاه، وعلى إنشاء مهمة دورية باسم `CodexTeamMeter`. للتثبيت التفاعلي بدل الموافقة بالأعلام:

```powershell
node .\install.mjs
```

سيُطلب مسار ملف الربط، ثم `YES` للموافقة على القياس، ثم `YES` لتشغيله تلقائيًا. لا تضع المفتاح نفسه في سطر الأوامر أو محادثة Codex.

المثبت يضع السكيل في:

```text
%USERPROFILE%\.agents\skills\team-usage-meter
```

ويحفظ مفتاح المرصد وحالة القياس محليًا في:

```text
%USERPROFILE%\.codex-team-meter
```

المهمة المجدولة تعمل كل دقيقة بصلاحيات المستخدم الحالي؛ قد تتطلب سياسة جهاز العمل السماح بإنشاء مهمة. إذا فشل التسجيل سيظهر تحذير، ولا يجوز اعتبار التشغيل التلقائي ناجحًا. لا تشغّل المثبت كمسؤول إلا إذا كنت تفهم سياسة جهازك، لأنه يجب أن يقرأ ملفات المستخدم الذي يشغّل Codex نفسه.

بعد التثبيت افتح جلسة Codex جديدة حتى يكتشف السكيل. للتأكد من المرسل من PowerShell:

```powershell
node "$env:USERPROFILE\.agents\skills\team-usage-meter\scripts\agent.mjs" status
schtasks /Query /TN CodexTeamMeter /V /FO LIST
```

لإرسال فوري:

```powershell
node "$env:USERPROFILE\.agents\skills\team-usage-meter\scripts\agent.mjs" once
```

أو داخل Codex:

```text
$team-usage-meter افحص حالة المزامنة بدون فتح المحادثات أو ملفات المفاتيح
```

لا يلزم استدعاء السكيل مع كل مهمة؛ المزامنة مستقلة عنها.

## Linux وmacOS

نفس ملفات Node تعمل دون Python أو حزم npm إضافية:

```bash
node ./install.mjs --profile /path/to/member-profile.json --accept --autostart
node ~/.agents/skills/team-usage-meter/scripts/agent.mjs status
```

على Linux يُنشأ مؤقت systemd خاص بالمستخدم، وعلى macOS يُنشأ LaunchAgent. عادة يتطلبان بقاء جلسة المستخدم فعالة. هذه أوامر التثبيت موجودة في المصدر لكنها لم تُختبر على كل نظام تشغيل خلال إعداد الحزمة.

عند عدم توفر مدير الخدمات، شغّل المرسل في نافذة طرفية مخصصة:

```bash
node ~/.agents/skills/team-usage-meter/scripts/agent.mjs watch
```

هذا الوضع يزامن كل 15 ثانية ما دامت النافذة تعمل. لا تشغّل عدة نسخ على نفس مجلد Codex. يوجد قفل لمنع التشغيل المتداخل، لكنه ليس بديلًا عن إعداد صحيح.

## اختيار مجلد Codex الصحيح

الافتراضي هو `CODEX_HOME` إن كان معرّفًا، وإلا `~/.codex`. لا يعتمد البرنامج على محادثات ChatGPT في المتصفح.

عند استخدام VS Code مع WSL أو SSH أو Dev Containers، ثبّت المرسل **في البيئة التي توجد فيها سجلات Codex فعلًا**. المرسل على Windows لا يقرأ ملفات Linux البعيدة تلقائيًا. لتحديد مسار غير افتراضي عند التثبيت الأول:

```powershell
node .\install.mjs --profile "C:\path\member-profile.json" --codex-home "D:\my-codex-home" --accept --autostart
```

استخدم حساب مستخدم نظام منفصل لكل شخص عندما يكون الجهاز مشتركًا. لا تنسب مجلد Codex واحدًا لشخصين، ولا تنسخ ملف إعداد المرسل مع معرّف الجهاز إلى جهاز آخر. التثبيت الجديد على جهاز آخر يولد معرّف جهاز جديدًا.

## كيف تتأكد أنه يعمل؟

ابدأ مهمة Codex محلية صغيرة بعد التثبيت. انتظر تسجيل عداد توكنز ثم دقيقة تقريبًا. شغّل `status` وافتح اللوحة بمفتاح العضو نفسه الموجود في ملف الربط. لا تضع كلمة مرور ChatGPT في اللوحة.

- `last_success`: آخر مزامنة ناجحة، وليس آخر مرة كان فيها الشخص يعمل.
- `files_found`: عدد ملفات rollout التي عثر عليها المرسل. صفر يعني أن المصدر غير موجود أو المسار غير صحيح أو أن الإصدار يستخدم تنسيقًا مختلفًا، وليس أن استخدام الشخص مؤكد أنه صفر.
- `pending`: أحداث أرقام تنتظر الإرسال.
- `issues`: حالات تخطٍّ أو انقطاع في العدادات قد تجعل النتيجة ناقصة.
- `conflicts`: بصمات استخدام سبق إسنادها لعضو آخر، مثل نسخ السجلات؛ لا تُحسب مرتين.
- `expired`: أحداث قديمة جدًا سقطت خارج احتفاظ السيرفر البالغ 90 يومًا.

إذا ظهرت `HTTP 401` فالمرسل يحتاج مفتاح عضو صالحًا. إذا ظهر `HTTP 400` فتوقف عن التخمين وراجع التوافق العددي/تنسيق السجل. لا ترسل ملفات rollout أو `config.json` للتشخيص؛ يكفي `status` ورسالة الخطأ المختصرة.

## الإزالة

```powershell
node "$env:USERPROFILE\.agents\skills\team-usage-meter\uninstall.mjs"
```

أو على Linux/macOS:

```bash
node ~/.agents/skills/team-usage-meter/uninstall.mjs
```

يلغي التشغيل التلقائي ثم يسأل قبل حذف ملفات المرصد المحلية. أغلق أي عملية `watch` بدأتَها يدويًا. لا يُحذف أي ملف تابع لـ Codex. الأرقام السابقة على السيرفر تبقى حتى انتهاء الاحتفاظ، ويمكن للمدير إيقاف مفتاحك من اللوحة.
