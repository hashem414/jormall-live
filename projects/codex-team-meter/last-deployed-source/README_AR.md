# مرصد كودكس — Codex Team Meter

نسخة 1.0.0 | 20 سبتمبر 2026

**الموجود هنا برنامج قابل للتشغيل محليًا مع ملفات نشر، وليس موقعًا منشورًا مسبقًا.** يلزم تشغيل السيرفر على استضافة فعلية وربط أجهزة الأعضاء به. لا توجد مفاتيح أو حسابات OpenAI داخل الحزمة.

## ماذا يفعل؟

لوحة عربية خاصة تعرض اسم كل عضو، إجمالي توكنزه المرصودة ونسبتها من مجموع توكنز الفريق، المدخلات والمخرجات والكاش، وآخر اتصال للمرسل. تتضمن فترات آخر 5 ساعات و24 ساعة و7 أيام و30 يومًا و90 يومًا، ولقطات حدود الحساب عندما يسجلها Codex، وتصدير CSV، وإضافة الأعضاء وإيقاف مفاتيحهم.

يتكون النظام من سكيل لكل عضو، ومرسل Node محلي، وسيرفر Node/SQLite دائم، وواجهة عربية. لا توجد مكتبات npm خارجية أو Python في المشروع. المزامنة الدورية لا تستدعي موديل OpenAI.

```text
Codex المحلي على جهاز العضو
        │ يكتب ملفات rollout
        ▼
مرسل محلي بموافقة العضو
        │ يستخرج العدادات ويترك نص المحادثة على الجهاز
        │ HTTPS: أرقام + معرّفات مبهمة فقط
        ▼
سيرفر Node + SQLite ──► لوحة عربية محمية بتسجيل دخول
```

## أهم حدود القياس

**هذه ليست النسبة الرسمية لاستهلاك كل شخص من اشتراك Pro.** النسبة المعروضة هي:

```text
حصة العضو = توكنزه المرصودة خلال الفترة / مجموع توكنز الفريق المرصودة خلالها × 100
```

على سبيل المثال، 30,000 من أصل 100,000 توكن مرصود = 30% من المرصود، لا 30% من باقة OpenAI. تختلف آثار التوكنز على الحصة باختلاف النموذج والكاش والتفكير والأدوات وغيرها. لا نستخدم أسعار API كأنها فوترة Pro، ولا نحسب الفرق بين نسب الحساب أثناء الاستخدام المتزامن على أنه يخص عضوًا معينًا.

توكنز الكاش ضمن المدخلات وتوكنز التفكير ضمن المخرجات؛ لا نجمعها مرتين. الفترات المعروضة متحركة، وليست محاكاة لنوافذ إعادة ضبط اشتراك OpenAI.

لقطة حدود الحساب تُعرض باسم الجهاز الذي رصدها مع وقت الرصد ومدة النافذة وموعد التجدد. هذه **لقطة عن الحساب** وليست استهلاك ذلك العضو. لا نجمع أو نعدل أو ندمج لقطات أعضاء مختلفين لأن حساباتهم قد تكون منفصلة. إذا انتهى موعد النافذة أو قدمت اللقطة توضح اللوحة أنها ليست النسبة الحالية.

المصدر هو ملفات Codex المحلية `sessions` و`archived_sessions` التي تحمل اسم `rollout-*.jsonl` وبنية `event_msg/token_count`. لا يوجد التقاط تلقائي كامل لمهام Codex Cloud أو ChatGPT Work أو GitHub Reviews أو استعمال المتصفح أو أجهزة لم يُثبت عليها المرسل. قد تظهر بعض تلك الأعمال محليًا لكن لا نعد بذلك. أي إصدار لا ينتج البنية المتوافقة يحتاج تعديل المرسل.

القياس يبدأ من تثبيت كل عضو. العدادات السابقة تُستخدم كأساس محلي لتفادي احتساب التاريخ القديم، ولا تُرفع كاستخدام جديد. حالات تغيّر عداد أو سياق موروث لا يمكن التأكد منه تُتخطى بدل اختراع أرقام. ليست الأداة مراقبة خفية أو مقاومة لتلاعب مالك الجهاز، ولا تمنع استعمال Codex إذا أوقف العضو المرسل.

وفق سياسة OpenAI، الحساب الشخصي ليس للمشاركة بين أشخاص. الأداة لا تغيّر شروط الاشتراك ولا توفّر عزل محادثات داخل حساب مشترك؛ عدم إرسال المحادثات يخص **هذه اللوحة فقط**.

## تشغيل محلي أولًا — للمدير

تحتاج Node.js 22.16 أو أحدث، ويفضل تشغيل السيرفر بإصدار Node 24 كما في Dockerfile. على جهاز العضو يكفي Node 20+. لا يلزم `npm install` لأن البرنامج يستخدم الوحدات المدمجة فقط. Node 22 قد يعرض تحذير أن SQLite تجريبي.

افتح الطرفية داخل مجلد المشروع:

```bash
node deploy/setup.mjs
npm test
npm start
```

افتح:

```text
http://localhost:8790
```

سيُنشأ ملف `.env` خاص فيه `ADMIN_TOKEN`. افتحه بنفسك في محرر نصوص محلي، وانسخ المفتاح إلى خانة الدخول. **لا ترسل الملف للتيم ولا تلصق محتواه في محادثة AI.** هذا مفتاح مرصدك وليس كلمة مرور ChatGPT.

العنوان `localhost` يعمل على جهازك فقط ولا يصلح كعنوان ترسله إلى أجهزة الفريق. انتقل للنشر قبل إنشاء ملفات الربط التي ستوزعها.

## نشر دائم على Ubuntu/Docker بجانب n8n

هذا المشروع مستقل ولا يعدّل حاوية n8n أو قاعدة بياناتها أو ملفات مواقع nginx الموجودة. تأكد أن المنفذ 8790 غير مستخدم. تحتاج Docker Compose، واسم نطاق فرعي موجّه إلى سيرفرك، وnginx وHTTPS.

في مجلد جديد على السيرفر، بعد نقل الحزمة وفكها:

```bash
node deploy/setup.mjs --url https://usage.YOUR-DOMAIN.com
docker compose up -d --build
docker compose ps
```

استبدل العنوان بعنوانك الحقيقي. إن كان `.env` موجودًا من التجربة المحلية، المثبت لا يمسحه ولا يبدل مفاتيحك؛ عدّل `PUBLIC_URL` فيه يدويًا ثم أعد تشغيل الحاوية. يجب أن يكون أصل الموقع بلا مسار فرعي، مثل `https://usage.company.com`، لا `/meter`.

المنفذ مربوط افتراضيًا بـ `127.0.0.1:8790` على السيرفر، كي يمر الإنترنت عبر nginx وTLS فقط. بيانات SQLite محفوظة في Docker volume اسمه المنطقي `meter-data`. لا تستعمل `docker compose down -v` لأنه يحذف هذا القرص بما فيه الاستخدام.

لإضافة موقع nginx **جديد**:

```bash
sudo cp deploy/nginx.conf.example /etc/nginx/sites-available/codex-team-meter
sudo nano /etc/nginx/sites-available/codex-team-meter
```

غيّر `usage.example.com` في الملف الجديد إلى نطاقك، ثم:

```bash
sudo ln -s /etc/nginx/sites-available/codex-team-meter /etc/nginx/sites-enabled/codex-team-meter
sudo nginx -t
sudo systemctl reload nginx
```

إذا كان الرابط الرمزي موجودًا، راجعه بدل استبداله عشوائيًا. ملف المثال HTTP فقط لبدء إعداد الشهادة. فعّل شهادة TLS بالطريقة المعتمدة على سيرفرك؛ عند وجود Certbot مع إضافة nginx يكون الأمر المعتاد:

```bash
sudo certbot --nginx -d usage.YOUR-DOMAIN.com
```

اختر التحويل إلى HTTPS. لا تسجل الدخول ولا توزع المفاتيح قبل نجاح HTTPS. تأكد من فتح 80/443 حسب إعداد شبكتك ومن صحة DNS، ولا تفتح 8790 للإنترنت. عدم توفر هذه الإعدادات يعني أن الموقع لم يصبح أونلاين بمجرد فك الضغط.

لفحص الحاوية محليًا دون كشف المفاتيح:

```bash
curl http://127.0.0.1:8790/healthz
docker compose logs --tail=30 meter
```

لا ترسل `docker compose config` كاملًا أو `docker inspect` كاملًا للمحادثة؛ قد يظهر المفتاح في متغيرات البيئة. الحاوية تستخدم `restart: unless-stopped` وتحتفظ بقاعدة البيانات؛ استمرارية الموقع ما زالت تعتمد على عمل السيرفر والتخزين والشبكة.

### نشر على استضافة تدعم Docker

يمكن نشر Dockerfile بدل إدارة Ubuntu. يحتاج التطبيق خدمة دائمة واحدة وقرصًا دائمًا لـ SQLite؛ لا تنشره كصفحة static أو وظيفة مؤقتة أو نسخ متعددة تتشارك ملف SQLite عبر شبكة.

أرفق `railway.json` كقالب نشر اختياري. عند استخدام Railway تحتاج ربط حساب الاستضافة أولًا، وإنشاء الخدمة والقرص وتعيين `ADMIN_TOKEN` العشوائي و`PUBLIC_URL` إلى الدومين الفعلي و`DATA_DIR` إلى مجلد القرص. يعرض التطبيق `/healthz` ويستمع إلى `PORT` الذي توفره البيئة. تأكد أن مستخدم الحاوية `node` قادر على الكتابة في القرص؛ صلاحيات قرص المنصة ليست مضمونة من هذه الحزمة. عطّل السكون/Serverless إن كنت تريد بقاء المرسل واللوحة متاحين باستمرار. لم يُنفذ نشر Railway في الاختبارات المرفقة.

## توزيع السكيل على الفريق

بعد نجاح HTTPS، ادخل كمدير ثم أدخل اسم كل شخص في «إضافة عضو». لكل شخص مفتاح مستقل. نزّل ملف `member-profile.json` فورًا عند إنشائه؛ لا يُخزن المفتاح بالنص الخام في جدول الأعضاء ولا يُعرض مرة ثانية. أرسل حزمة `Codex_Team_Meter_TEAM_SKILL.zip` للجميع، وأرسل ملف الربط الخاص بكل عضو له وحده. لا تشارك ملف المدير أو ملف عضو مع بقية الفريق.

إذا ضاع مفتاح العضو، أوقف القديم وأنشئ سجلًا جديدًا. ستظل الأرقام القديمة ظاهرة باسم السجل القديم خلال فترة الاحتفاظ. النسخة الحالية لا تتضمن دمج السجلات أو استرجاع المفاتيح القديمة.

يفتح العضو مجلد `team-usage-meter` ويشغل:

```powershell
node .\install.mjs --profile "C:\path\member-profile.json" --accept --autostart
```

أرسل معه `skills/team-usage-meter/README_AR.md`؛ يتضمن Windows وLinux وmacOS وWSL، والموافقة، والفحص والإزالة. لا يحتاج جهاز العضو تشغيل السيرفر أو فتح Dashboard طوال الوقت، لكن يحتاج المرسل العمل في البيئة التي يستخدم فيها Codex.

## الصلاحيات والخصوصية

المدير يضيف الأعضاء ويوقف مفاتيحهم ويرى الملخص. العضو يستطيع تسجيل أرقام جهازه وعرض ملخص الفريق. السيرفر يحدد صاحب الأرقام من مفتاحه، ولا يثق باسم عضو يرسله الجهاز في جسم الطلب. يوجد منع لإسناد معرّف جهاز موجود لشخص آخر، ومنع لاحتساب بصمة حدث ثانية حتى لو وصلت من جهاز مختلف.

السيرفر يقبل مخططًا محدودًا بالأرقام ومعرّفات مبهمة، ويرفض الحقول الإضافية مثل `prompt` أو `conversation`. لا يوجد endpoint لقراءة محادثة أو مسار مشروع. سجلات التطبيق لا تطبع الطلبات أو المفاتيح؛ تأكد بنفسك من إعداد أي reverse proxy أو مراقبة خارجية تضيفها.

المفتاح الإداري سر عشوائي، ومفاتيح الأعضاء محفوظة في قاعدة البيانات كبصمات SHA-256 لرموز عالية العشوائية. جلسة المتصفح ثماني ساعات، باستخدام cookie من نوع HttpOnly وSameSite=Strict وSecure عند HTTPS. لا تُخزن المفاتيح في localStorage أو روابط URL. ملفات اعتماد المرسل محلية وصلاحياتها مقيدة قدر الإمكان.

لا يعد ذلك تدقيقًا أمنيًا مستقلًا. مالك الجهاز أو مستخدم root يستطيع تغيير المرسل أو قراءة بيانات الجهاز. مالك الاستضافة يرى الأرقام وبيانات الاتصال، وربما IP على مستوى مزود الاستضافة. لا تُدرج معلومات حساسة في اسم العضو.

## التشغيل والصيانة

المرسل المثبت يزامن تقريبًا كل دقيقة. وضع `watch` يزامن كل 15 ثانية. اللوحة تُحدّث كل 15 ثانية عندما تكون الصفحة ظاهرة. «متصل» يعني وصول مزامنة خلال ثلاث دقائق، وليس مراقبة لوحة المفاتيح أو إثبات وجود الشخص أمام الجهاز.

تُحفظ الأحداث الرقمية مع مواضع القراءة قبل الإرسال؛ لا يحذف المرسل الحدث من الطابور إلا بعد إقرار السيرفر. تمنع بصمة الحدث التكرار عند إعادة المحاولة أو بعد انقطاع الرد. لا ينتقل محتوى المحادثة إلى الطابور أو حالة المرسل.

البيانات العددية على السيرفر تُحذف بعد 90 يومًا بواسطة مهمة صيانة دورية؛ بيانات العضوية وآخر اتصال وآخر لقطة حدود تبقى. قد تتأخر الإزالة حتى جولة الصيانة التالية، وقد تظل نسخ قديمة في backups أو صفحات SQLite الحرة حتى إعادة تنظيم الملف؛ هذه ليست أداة محو جنائي. البيانات المعلقة أكثر من 90 يومًا يُقر السيرفر بأنها قديمة ويستبعدها، ويعرض المرسل عددها في `expired`.

شغّل نسخة واحدة من السيرفر. خذ نسخًا احتياطية آمنة من القرص والملف `.env`، لا من `.sqlite` وحده أثناء كتابة WAL. يمكن إيقاف الخدمة فترة قصيرة عند نسخ القرص بالكامل؛ ستصفّ الأجهزة الأرقام المعلقة حتى عودة السيرفر. اختبر استعادة النسخة الاحتياطية قبل الاعتماد عليها.

## تجربة قبول قبل تعميم النظام

ابدأ بعضو واحد: ثبّت المرسل، نفذ مهمة Codex محلية جديدة، وتأكد من ظهور ملف rollout متوافق ومن زيادة أرقام العضو في اللوحة. أعد الإرسال وتأكد أن الإجمالي لم يتكرر. افصل اتصال المرسل مؤقتًا، نفذ استخدامًا جديدًا ثم أعد الاتصال وتحقق من تصفير الطابور. بعد ذلك أضف عضوًا ثانيًا وتأكد من فصل الأسماء. قارن اتجاه الأرقام مع إحصائيات Codex؛ لا تتوقع تطابق نسبة التوكنز مع نسبة الباقة.

لا ترسل ملفات المحادثات أو `auth.json` من أجل هذه التجربة. حالة `status` والأخطاء المختصرة تكفي كبداية للتشخيص.

## حالة الاختبار

راجع `docs/TEST_REPORT.md`. الاختبارات المحلية تستخدم سجلات اصطناعية، وسيرفر HTTP حقيقيًا داخل بيئة الاختبار، وواجهة Chromium ببيانات اصطناعية. لم يُختبر ربط حساب OpenAI فعلي، ولم تُنفذ مهام بدء التشغيل على Windows/macOS، ولم يُنشر المشروع على نطاق عام أو يُبنَ Docker image داخل هذه البيئة. صور المعاينة موسومة بأنها بيانات تجريبية.

## الملفات

- `server/`: HTTP، المصادقة، التحقق الصارم من البيانات، والتجميع في SQLite.
- `public/`: لوحة عربية بدون ملفات أو مكتبات واجهة خارجية.
- `skills/team-usage-meter/`: الحزمة التي تثبت على أجهزة الأعضاء.
- `deploy/`, `Dockerfile`, `compose.yaml`: إعدادات التشغيل والنشر.
- `tests/`: الاختبارات القابلة للتشغيل بـ `npm test`.
- `docs/`: المعاينات وتقرير الاختبار والمصادر.

المصادر الأولية وحدود الاستدلال موثقة في `docs/SOURCES.md`.
